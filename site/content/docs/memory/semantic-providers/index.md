Documents and their revisions remain authoritative. A save commits locally before the delivery queue sends a revision to the selected service. Recall rechecks membership, ownership, deletion, revision and any returned content hash after the HTTP request. A citation identifies a source revision; it does not certify an extracted conclusion. Untraceable results from an authorized document partition say `from <provider>, unverified`. Compacted thread summaries stay local.

| Service | What it stores | What leaves the API/worker machine |
| --- | --- | --- |
| Mem0 platform (`mem0`) | Extracted facts and embeddings; document ID, revision, content hash and namespace metadata | Revision text and recall queries go to `api.mem0.ai` |
| Mem0 self-hosted (`mem0-oss`) | Facts and embeddings in the owner's configured Mem0 store, with the same metadata | Text and queries go to the configured host and any extraction/embedding services it uses |
| Graphiti (`graphiti`) | Revision episodes, entities and temporal relationship edges in a document-scoped group | Text, queries and source metadata go to the configured host and its model/embedding services |

Graphiti is offered for temporal relationships and episode provenance. Document-scoped groups prevent graph extraction from merging differently authorized documents; this deliberately gives up relationships across documents. No benchmark ranking is implied. Hosted requests, extraction and embeddings can incur charges; changing services reindexes every current revision. A local container may still call a hosted model. No new runtime dependency or vendor SDK is bundled: HTTP code stays in `packages/adapters`, using fetch and the existing DNS-pinned transport.

## Connect and verify

1. As a space owner, open **Settings → Memory → Another service**. Choose **Mem0 platform**, enter an API key, and check `Sends memory text to api.mem0.ai`. For self-hosting, start the official [Mem0 server](https://github.com/mem0ai/mem0/tree/main/server) or [Graphiti REST service](https://github.com/getzep/graphiti/tree/main/server), then choose its entry and enter the URL reachable by the API **and worker**. Container loopback refers to that container. Mem0 accepts an optional API key; Graphiti accepts an optional bearer token for a deployment's authenticated proxy.
2. Select **Test connection**, review the document/revision counts, then **Use this location**. Testing performs a scoped read without submitting memory text. Saving tests again before persisting encrypted credentials. Private endpoints require deployment-owner authorization, DNS is checked on every request, and redirects are rejected. Mem0 requires HTTPS for public hosts; Graphiti requires HTTPS for every non-loopback host. Graphiti front-door authentication remains distribution-specific and unverified; a successful read does not prove unauthenticated requests are denied.
3. Ask a bot to remember a harmless distinctive fact, or edit an existing document. Its revision is saved first. Watch `Indexed X of Y` for the documents visible to you. Pending/failed revisions remain readable with **Retry**. Mem0 platform delivery waits for event `SUCCEEDED`; Graphiti waits until its matching episode is readable. Reopen the document to refresh its delivery badge. Mobile shows the destination and documents read-only.
4. Ask the same bot to recall the fact. A traceable result carries `[ardur-memory:<documentId>:<revision>]`; compare it with the document's History. Edit the document, wait for indexing, and confirm that the old revision is excluded. Disconnect the service and confirm the documents and history remain readable.

Changing a service preserves the document bundle and queues current heads under a new configuration generation. The existing location preview migrates Obsidian/Git documents to the built-in companion journal before attaching semantic recall; the original external files remain. Credentials, delivery receipts and retry times are excluded from portable exports. The core product needs no semantic service.

## Verified HTTP contracts — 2026-09-23

| Transport | Routes used | Primary source |
| --- | --- | --- |
| Mem0 platform, `filterVersion=platform-v3`, `Authorization: Token …` | `POST /v3/memories/add/`; `GET /v1/event/{event_id}/`; `POST /v3/memories/search/`; `POST /v3/memories/?page=N&page_size=200`; `DELETE /v1/memories/{memory_id}/` | [Quickstart](https://docs.mem0.ai/platform/quickstart), [add](https://docs.mem0.ai/api-reference/memory/add-memories), [event](https://docs.mem0.ai/api-reference/events/get-event), [search](https://docs.mem0.ai/api-reference/memory/search-memories), [list](https://docs.mem0.ai/api-reference/memory/get-memories), [delete](https://docs.mem0.ai/api-reference/memory/delete-memory) |
| Mem0 OSS, `filterVersion=oss-filters-v1`, optional `X-API-Key` | `POST /memories`; `POST /search`; `GET /memories?user_id=…&top_k=1000&show_expired=true`; `DELETE /memories/{memory_id}` | [OSS overview](https://docs.mem0.ai/open-source/overview), [REST guide](https://docs.mem0.ai/open-source/features/rest-api), [server routes and request models](https://github.com/mem0ai/mem0/blob/main/server/main.py) |
| Graphiti, `serviceVersion=graphiti-rest-v1`, optional `Authorization: Bearer …` | `POST /messages`; `GET /episodes/{group_id}?last_n=10000`; `POST /search`; `DELETE /group/{group_id}`; `GET`/`DELETE /entity-edge/{uuid}` | [REST service](https://github.com/getzep/graphiti#rest-service), [ingest routes](https://github.com/getzep/graphiti/blob/main/server/graph_service/routers/ingest.py), [retrieve routes](https://github.com/getzep/graphiti/blob/main/server/graph_service/routers/retrieve.py), [response mapping](https://github.com/getzep/graphiti/blob/main/server/graph_service/zep_graphiti.py) |

Mem0 search entity IDs are inside `filters`, never top-level. Each document revision also gets a derived `run_id` on add and search so extraction deduplication cannot leave a new revision pointing at old metadata; cleanup still enumerates the whole document namespace. Both the [platform add contract](https://docs.mem0.ai/api-reference/memory/add-memories) and the [OSS scope builder](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py) support this scope. The REST guide still shows older top-level OSS search examples and refers broadly to platform V1 paths; the current request model and operation references above define this adapter's versioned contract. Mem0 deletion enumerates a scoped namespace, validates our metadata locally, then deletes exact IDs. No free-text entity deletion or global reset is used. OSS pagination beyond its 1,000-item list ceiling is unsupported because no cursor is documented; cleanup fails visibly at that ceiling. Graphiti episode lookup is bounded to the latest 10,000 episodes per document; older unresolvable episode citations are excluded.

## Revoke and erase

Switch to **Built-in**, preview, and confirm to stop new semantic deliveries; revoke the platform API key, the OSS per-user key, or the Graphiti proxy token at its issuer. To remove remote copies, delete documents and let deletion finish **before** revoking access, or use the old service's administrative erasure procedure. Replacing/disconnecting a service does not erase its old data, backups or provider history. Mem0 cleanup selects only metadata-owned facts; Graphiti deletes the document group, including its episodes and edges. History purge targets only requested generation namespaces. The optional adapter `forget` operation verifies ownership before deleting a fact; the bot's forget tool tombstones the authoritative document through the lifecycle.

Neither service documents cancellation of in-flight ingestion in the contract used here. Erasure of late vendor writes therefore requires the service owner's verification after ingestion settles; deleted documents are immediately excluded from Ardur recall. Graphiti's service queue is in memory: after a server restart loses an accepted episode, **Retry** resubmits using the same deterministic episode ID. Mem0 exposes no documented add idempotency key; a crash between remote acceptance and saving its receipt can cause duplicate extraction work. Persisted receipts prevent resubmission during ordinary retries. Pin and smoke-test the deployed server version before use; automated tests use offline transports, not vendor accounts.
