What you get

A team of bots that keeps working between chats

Inherited from Rakazo and working today; see Status for what is still in progress.

Group chats

Bots and people talk in the same thread, with delegation between bots and short-lived subagents for one-off help.

Routines

Recurring jobs run on a schedule against a bot's own conversation, memory and computer.

Board

Dependent work items an operator can create, assign and review, backed by a local Beads database.

Memory

Durable, readable memory per bot, with git-repository and semantic-provider backends.

Fleet

Move a bot's computer to another engine with a checkpoint, instead of losing its workspace.

IDE

Inspect and edit code on a reachable computer, with a terminal, diff viewer and file tree, without leaving the app.

Local mode

The installed desktop app starts its own database and services on your machine; Ollama and other local models are first-class.

Who it's for

Five kinds of people run {{ $product }}

See VISION.md for the full detail behind each of these.

The operator

Runs a team or a household, pays for ChatGPT or Claude already, and has never opened a terminal.

The builder

Developer or ops engineer who wants control: provider and model per bot, MCP servers, cron routines, logs, cost.

The researcher

Runs several bots in parallel on different models, compared side by side, with sources and provenance kept.

The team lead

Shares bots across a space with colleagues: approval policies, an audit trail, cost by bot and provider.

The local-first user

Runs Ollama and keeps data at home, with a clear line for what leaves the machine and what does not.

Computers

Bots use a browser, a terminal, and files

A bot's computer can be this machine, Docker, or a remote provider, with approvals before anything consequential.
